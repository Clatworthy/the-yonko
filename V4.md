# Yonko V4

## First principle

```text
Protocol governs process.
Evidence governs decisions.
```

Companion: Information Preservation - Yonko may optimise representation, but it must
never optimise away engineering information.

**V3.4 is a stabilisation milestone.** Prefer use, friction notes, and deletion over
new features. The next architectural change should be driven by observed protocol
pain, not a feature roadmap.

V3.1 Evidence Index remains. V4 Phase 1 (3.2.0) adds observational Engineering
Efficiency reporting and safe structural token-waste removal. V3.4 adds authoritative
workflow legality (file-backed scripts only - no runtime).

| Era | Observes |

Loop (non-negotiable):

```text
Observe -> Measure -> Understand -> Optimise
```

Never:

```text
Guess -> Optimise -> Hope
```

## Engineering principle: no optimisation without evidence

Evidence Graph and execution profiles (3.8.x) are harness features. They are not
V4 auto-tune.

Yonko must **not** automatically change review behaviour, seating, packet
construction, or retrieval strategy based solely on observational metrics.

- Metrics inform engineering decisions.
- Humans make optimisation decisions.
- Scripts stay deterministic.
- Seats do not disappear automatically.
- Packet hard budgets do not silently change.
- Prompts do not mutate from metrics.

## Packet principle

```text
Full relevant context ≠ Full available context
Maximum relevant context ≠ Maximum context
```

## Information Preservation Principle (hard rule)

```text
Yonko may optimise representation, but it must never optimise away engineering information.
```

| Allowed | Not allowed |
|---------|-------------|
| Deduplicate exact / safely normalised repeated prose | Summarise changed code |
| Replace duplicates with stable references | Summarise tests |
| Compress repeated ceremony and seat-prompt boilerplate | Summarise contracts / OpenAPI / schemas |
| Omit plan-session noise (findings, dialogue, prior packets) outside the handoff contract | Summarise migrations / backfills |
| Bound reviewer *output* to material findings | Summarise deployment ordering / rollout / rollback |

**Verbatim forever (in the packet):** diffs, tests, contracts, migrations, and deployment-ordering
statements that are unique engineering content. Representation may change only via
dedupe-to-reference of *identical* prose, never via lossy summary.

Phase 1 scripts enforce the DIFF / fenced-code half mechanically
(`packet_ops.dedupe_packet`). Lossy summary modes are forbidden until a later phase
passes the acceptance criteria below.

## Acceptance criteria: optimisation must preserve review quality

Do not trust token savings alone. Measure.

For every structural optimisation that changes packet bytes:

1. Build **Original packet** (optimisation off or pre-transform).
2. Build **Optimised packet** (optimisation on).
3. Prove **information preservation** mechanically where possible
   (`scripts/lib/information_preservation.py` / smoke tests):
   - every `=== DIFF: … ===` body byte-identical
   - every fenced code block byte-identical
   - no unique engineering paragraph deleted without a `[dedup:ref=…]` pointing at a
     retained canonical copy
4. For representative fixtures, run the **same council** on both packets and compare:

| Compare | Rule |
|---------|------|
| Material findings | Optimised must not produce *fewer* material findings unless each miss is explicitly justified |
| **Finding coverage** | Optimised must preserve issue *classes*, not only counts. Losing `security` while gaining `documentation` at the same count is a fail |
| Severities | No silent severity downgrades on shared findings |
| Evidence references | Locus / evidence must remain resolvable against the optimised packet (or its refs) |
| Verifier outcome | Must not weaken (confirmed → rejected) without written justification |
| Engineering Confidence | Must not drop solely because of representation changes |

Suggested coverage categories (Chair maps findings; may add labels):
`correctness`, `architecture`, `concurrency`, `security`, `performance`,
`compatibility`, `testing`, `operability`, `data-integrity`, `api-contract`, `other`.

Differences must be explained in the session or in
`templates/optimisation-quality-acceptance.md`.

Do not hardcode a token-savings target. Savings remain a **hypothesis until 10–20 real
Efficiency Reports** (and dual-council fixture compares) exist. Report measured rates
after the fact; do not promise a percentage up front.

The standard: **cheaper and equally rigorous** - or do not ship the optimisation.

Harness: `scripts/compare-optimisation-quality.sh` records dual-run comparison JSON.
Automated smokes prove the mechanical half; dual council runs remain Chair-led until
fixtures are checked in.

## V4 Phase 0 - shadow workflow (shipped as 3.3.0)

Session artefacts only: `workflow.json` + `workflow-events.jsonl`.
Mode was always `shadow`. Guards recorded `would_block` and failure codes; they never
blocked scripts, changed packets, seating, prompts, or Evidence Index behaviour.
Observation is automatic via `record-event.sh` and script hooks - Chair does not
maintain workflow state.

## V4 Phase 1 - authoritative workflow legality (shipped as 3.4.0)

**Protocol governs process. Evidence governs decisions.**

Still file-backed and script-driven. No daemon, database, graph engine, or adaptive
routing. New sessions default to `enforce` (`config/workflow-policy.yaml`).
Override: `YONKO_WORKFLOW_MODE=shadow`.

Authoritative guards (enforce fail-closed): open material findings, required
verification, reviewer completion, human plan/document approval metadata, packet
freshness / hash, confirmation budgets, review-type write fences, illegal ordering.
Narrow `human_override_legality` with explicit human reason. Deterministic
`scripts/workflow/explain.py`. Efficiency Report distinguishes shadow would_block vs
enforce blocked, overrides, repins, and failure counts (raw facts only).

See `scripts/workflow/README.md`.

## V4 Phase 1 - shipped (efficiency + structural waste)


### 1. Engineering Efficiency Report (observational)

Emitted at `finalize-session.sh` into `efficiency-report.json` and appended to
`SUMMARY.md`. Fail-open: report failure never invalidates a valid session.

Sections: Packet / Review / Knowledge / optional Workflow. Every report states
observational-only disclaimer. Does not influence seating, packets, prompts,
retrieval, or verification. Workflow metrics do not drive adaptive optimisation.

### 2. Safe structural waste removal (not adaptive)

| Change | Behaviour |
|--------|-----------|
| Linked-plan handoff | Implementation packets with `linked_session` embed scrubbed `PLAN.approved.md` only; exclude findings, prior packets, dialogue |
| Slim seat prompts | Ceremony (Evidence Index, lifecycle, metrics, Chair workflow) marked Chair-only |
| Packet deduplication | Exact/normalized paragraph duplicates → stable `[dedup:ref=N source=…]` + receipt; never DIFF sections or fenced code |
| Concise seat output | Material findings only; forbid praise / summaries / "checked fine" |

### Explicitly NOT in Phase 1

Staged seating, seat-count changes, cheaper models, code truncation/summaries,
packet hard limits, reduced verifier runs, adaptive retrieval weighting,
automatic economy mode.

## Phase 2+ (after 10–20 real sessions)

Only after Efficiency Reports show where cost actually comes from: further packet
discipline justified by data; quality-versus-cost trade-offs remain human-gated.
Any Phase 2 packet change must pass Information Preservation + the dual-council AC.
